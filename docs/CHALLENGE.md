## 90-second demonstration plan

| Time | Show | Explain |
|---|---|---|
| 0–12 s | A real repo with a small missing docstring | A useful chore that is easy to postpone. |
| 12–25 s | Local-only Ollama setup and `ghost doctor` | The model runs locally; tag and digest are visible. |
| 25–45 s | `ghost run --repo … --dry-run`, then dashboard | One bounded suggestion with a source quote and uncertainty. |
| 45–62 s | Expand evidence, read exact diff, approve | Review is tied to exact source and policy snapshots. |
| 62–75 s | Topic branch commit and untouched main worktree | Existing work is isolated; attribution is explicit. |
| 75–90 s | Re-run no-op / dirty-tree safe stop | Doing nothing is a deliberate, useful outcome. |

Use the fixture demo to practice, but label it **fixture, no model inference**. For the final AI demonstration, record an actual Ollama run on hardware you can describe. Do not edit the video to hide rejected or malformed outputs while claiming reliability.

## Write-up structure

- What I built: the developer problem and one concrete maintained function.
- Demo: actual recorded link; identify real inference versus fixture footage.
- Code: the real public repository URL after you publish it.
- How I built it: local Ollama, schema validation, CST/AST checks, isolated Git delivery.
- Why open innovation matters: model choice, inspectable implementation and locally controlled source context; acknowledge hardware cost and model licenses.
- Lazy payoff: measured review effort if you have it. Otherwise omit quantified savings.
- Limitations: missing-docstring/marked-Markdown scope, no production certification, real model quality and OS results actually observed.
- AI coding assistance: disclose that implementation used an AI coding assistant; do not claim wholly manual authorship.

Partner technology is optional for the overall entry. Do not add a hosted service solely to list a sponsor if it does not improve the local workflow. No partner-category eligibility is claimed here.
